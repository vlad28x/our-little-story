## Локальный запуск

Нужны Node.js **22.12 или новее** и npm. Проверено локально на Node 24.19.0. В терминале из корня проекта:

```sh
npm ci
npm run dev
```

Открыть адрес, напечатанный Vite (обычно http://127.0.0.1:5173/). Для телефона в той же локальной сети: `npm run dev -- --host 0.0.0.0`, затем открыть LAN-адрес компьютера, разрешив доступ в локальной сети при запросе системы. Clipboard и Web Share на обычном LAN HTTP могут быть недоступны; есть ручные варианты.

Локальный сервер должен оставаться запущенным, пока открыта игра: новые сцены подгружают изображения с него. Если сервер был остановлен, запустить его снова и обновить вкладку либо нажать «Повторить загрузку». Ошибка отдельного изображения не скрывает остальные слои; при смене эмоции/фона старое сообщение об ошибке не переносится на новую картинку. Повторная загрузка обходит закешированный неудачный запрос и не меняет игровой прогресс.

## Production-сборка и проверки

Если после обновления исходников появляется ошибка `Unknown asset vlad.casual.smile`, выполнить Ctrl+F5 без очистки localStorage. Все домашние эмоции теперь явно зарегистрированы в assetManifest.ts. Ошибка отрисовки или загрузки модуля показывает экран восстановления с конкретным сообщением, а не пустую страницу; сохранение автоматически не удаляется.

```sh
npm run typecheck
npm run lint
npm run test:unit
npm run validate:content
npm run build
npx playwright install chromium
npm run test:smoke
npm run test:offline
npm run preview
```

Исходники — `src/`, браузерная сборка — `dist/`. `dist/index.html` нужно обслуживать HTTP-сервером, не открывать через `file://`. Preview обычно доступен по http://127.0.0.1:4173/. `test:smoke` проверяет обслуживаемую production-сборку; сначала выполнить build. `test:offline` — отдельный изолированный Chromium без сети: настоящий клиент в production-режиме, локальные картинки как data URL и тестовая память вместо пользовательского localStorage; этот тест не обращается к локальной вкладке и не проверяет реальный URL. Тесты используют размеры Pixel 7 и 320×568. Это эмуляция в Chromium, не подтверждение проверки на настоящих Safari iPhone или Telegram.

В особой локальной среде Codex Node доступен отдельно от npm. Для текущей рабочей папки временно установлен npm в `work/tooling/package/bin/`; при необходимости можно вызвать `node work/tooling/package/bin/npm-cli.js run dev`. Это вспомогательная папка, в репозиторий и сборку не входит. Обычный установленный Node/npm на другом компьютере использует команды выше.

## Прогресс и резервные копии

Прогресс хранится только в текущем браузере и origin, под ключом `five-meetings:<basePath>:save`; предыдущая копия — `:backup`. При переименовании сайта с `/little-projects/` на `/our-little-story/` прежний прогресс автоматически читается в том же браузере, если у нового адреса ещё нет основной или резервной копии. Следующий сюжетный шаг записывается под новым ключом; старые данные остаются нетронутыми. Повреждённое старое сохранение открывает обычное восстановление. Другие пути и dev-режим изолированы. Переход в другой браузер или иная смена base path не переносит прогресс автоматически. В меню → «Настройки и резервная копия» можно скачать JSON и загрузить его на другом устройстве. Импорт заменяет текущую историю после предпросмотра; перед ним можно скачать свою копию. Лимит — 256 KiB. Неподходящие версии/повреждённые файлы отклоняются.

Перезагрузка диалога восстанавливает точную реплику. Незавершённый поиск начинается заново; сюжет перед ним сохранён. Поддерживается одна активная вкладка. При обнаружении более новой копии в другой вкладке игра предлагает загрузить её или скачать свой вариант; localStorage не является многопользовательской транзакционной системой.

Схема envelope осталась `schemaVersion:1`, версия контента теперь `contentVersion:10`. Старые сохранения выпусков 1–9 проверяются в прежних границах и обновляются автоматически, без сброса курсора, ответов, карточек, настроек и прав. Первый следующий шаг сохраняет новую версию, а предыдущий валидный JSON остаётся резервной копией. Незавершённый пазл зонтика после reload начинается заново; завершённый результат не повторяется.

Основная история имеет единственную версию каждой главы. Пробный повтор второй стартует из её исходного снимка и не меняет обе канонические главы. «Изменить мою историю» со второй сохраняет первую; с первой удаляет последующие основные результаты. Альбом и права остаются, вторую после изменения первой нужно пройти заново.

В обычном браузере нет аккаунтов, backend, БД, скрытой аналитики, автоматических сообщений или сетевой отправки прогресса. Этот режим запрашивает только собственные статические ресурсы; исключение нового Mini App — официальный SDK и облако Telegram (описаны ниже). Сообщение из финального приглашения можно скопировать и отправить вручную. Оригинальные фото и Telegram-материалы в проект, public и сборку не включены.

## Разработка и контент

Открытием глав 2–5 управляет автор через личную выдачу кода. Значение задаётся в `src/content/chapters/manifest.ts` (поле `code` у нужного `id`); после изменения нужна новая сборка. В интерфейсе код не показывается. Это управление ритмом игры на статическом сайте, а не защита секретного контента: код доступен в клиентских файлах. Ранее полученные права не отзываются сменой кода. Локальная памятка владельца исключена из Git и не входит в `dist/`.

- `src/engine/` — чистый движок, типы и валидатор графа.
- `src/content/chapters/ch01.ts` — все утверждённые реплики и узлы первой главы; сценарий не зашит в JSX.
- `src/content/chapters/ch02.ts` — сценарий второй; `index.ts` — реестр реально готовых глав.
- `src/state/` — транзакции истории, альбом и пробное прохождение.
- `src/persistence/` — проверка JSON, сохранение, резервная копия.
- `src/minigames/TokenSearch.tsx` — интерактивный поиск.
- `src/minigames/UmbrellaPatch.tsx` — пазл игрушечного зонтика.
- `src/content/chapters/ch03.ts` — третья глава.
- `src/minigames/Kitchen.tsx` и `kitchenModel.ts` — кухня на DOM/SVG и её чистая логика.
- `src/ui/`, `src/styles/` — игровая сцена и мобильный интерфейс.
- `src/sharing/` — скачивание JSON-копий и перенос выбранной копии из Telegram в браузер.
- `public/assets/` — готовые WebP; `ASSET_CREDITS.md` — происхождение арта.
- `outputs/` — утверждённое проектирование, сценарий и согласованный базовый образ.

Режим разработчика работает только на dev-сервере: меню → «Режим разработчика» или `?dev=1#/chapters`. У него отдельные ключи `:dev:save`/`:dev:backup`, экспорт отключён. Можно перейти к поиску, финалам первой главы, вступлению/пазлу/развязке второй с согласованным состоянием. Production не активирует этот режим.

Реализованы результаты `token-search`, `umbrella-patch`, `kitchen`, `constellation` и `memories`. Все пять глав доступны через реестр; незавершённая расстановка воспоминаний после reload начинается заново, подтверждённый результат сохраняется. При следующем расширении продолжать явную миграцию контента.

## Ограничения проверки

Реальные браузеры Telegram iOS/Android, Safari iPhone, системная отправка файлов на устройствах и читательский плейтест 5–7 минут требуют отдельной проверки владельцем. Фоновая музыка не подключена; есть отключаемые тихие синтезированные звуки действий. Арт сгенерирован и подключён; модель Влада одобрена автором в чате. Все пять глав и общие финалы реализованы.

## Третья глава

В квартире Влада три реакции на разряженный геймпад, три названия команды, две стратегии напарника и выбор после игры. Кухня: два учебных заказа без времени, затем три раунда по 25 секунд или без таймера. Первый ингредиент → «Передать Владу» → дождаться второго → «Подать». Три рецепта, две независимые тарелки, девять возможных подач. Ошибки не штрафуют. Между раундами перерыв; меню, сворачивание и потеря фокуса ставят игру на паузу. Возвращение требует кнопки, переход к спокойному режиму необратим в попытке. Пропуск доступен всегда. Reload возвращает к обучению, сохраняя сюжет до него.

Результаты: 7–9 feast, 3–6 snack, 0–2 chaos, отдельный skipped. Достижение за девять подач доступно в обоих режимах. Открытка содержит выбранное название команды. Пробный повтор третьей не меняет предыдущие главы; переписывание третьей сохраняет первые две, переписывание второй очищает третью. Игра управляется тапами, настоящие геймпады не нужны.


## Четвёртая глава

Новая вечерняя встреча на освещённой набережной. `teamName` и `gameAftercare` третьей меняют вступление. Место на скамейке меняет кадр и реакцию. В мини-игре сначала выбрать кота, один геймпад или чайник, затем собрать узнаваемый рисунок по подсвеченным звёздам: 17/12/16 точек, 2/1/3 отдельных контура. Общие точки и замыкание соединяются автоматически, детали загораются в конце. Есть отмена звезды, выбор другого рисунка и готовый чайник; во время рисования сцена уступает место большому полотну. Романтический, дружеский и неопределённый ответы равноправны; никакого автоматического прикосновения или штрафа за границы. Желание даёт «Созвездие приключений» или «Созвездие передышки». Рисунок показан на открытке результата, готовая картинка честно подписана. Пробный повтор не меняет каноническую открытку даже при замене такого же ID в альбоме.

Код задаётся владельцем в manifest и отправляется лично, свободной кнопки нет. Сохранения выпусков 1–3 мигрируют к контенту 4 без сброса. Reload рисунка сбрасывает только косметические точки. Пятая пока недоступна. Точные реплики — outputs/CHAPTER_04_SCRIPT.md; исходники — src/content/chapters/ch04.ts, src/minigames/Constellation.tsx, constellationModel.ts и src/ui/ConstellationArt.tsx.

`npm run test:offline` — отдельный браузерный тест четвёртой главы без сетевых запросов и сервера: код собирается для браузера в production-режиме, локальные иллюстрации подставляются data URL, localStorage заменяется тестовой памятью в отдельном профиле. Проверяются реальные нажатия, мобильный экран 320×568, клавиатура, открытка результата и пробное прохождение. Это дополняет обычный test:smoke; не заменяет будущую проверку на настоящем опубликованном GitHub Pages URL.

## Завершённая пятая глава

Точный сценарий: `outputs/CHAPTER_05_SCRIPT.md`. Исходники: `src/content/chapters/ch05.ts`, `src/content/memories.ts`, `src/minigames/Memories.tsx`, `src/content/invitation.ts`, `src/ui/InvitationPanel.tsx`. Новый арт: закатное кафе и три эмоции Влада в чёрном пиджаке. Остальные elegant-ключи — явные алиасы.

Три жетона ставятся тапами в любом порядке, повторный тап открывает воспоминание. «Положить вместе» доступно всегда, таймера и штрафов нет. Данные берутся из текущего прогона. Четыре явных финала доступны после любого bond. Награда «Пять встреч» выдаётся при каждом окончании без дублей. В коллекции всей игры до 12 открыток и пять достижений.

После любого основного финала пятой после открытки начинается разговор с Владом в оформлении visual novel. Подводка зависит от ending, дальше он вспоминает два проверенных геймпада и предлагает встречу. На каждой части разговора доступны пять ответов в порядке: «Игровой вечер», «Киновечер», «Встретиться в кафе», «Погулять вместе», «Отказаться». У каждого своя реакция, ответы всегда можно изменить. По умолчанию ничего не выбрано. `continuation` сохраняется только локально; редактируемый черновик в JSON не входит. Доступно только явное копирование сообщения для ручной отправки; для «Отказаться» черновика и копирования нет; Влад принимает отказ без уговоров. После завершённого пробного повтора пятой панель также доступна, если основная история уже завершена. При активном trial и просмотре альбома её нет. Старые public/chat/later сохраняются без подмены новым ответом; decline — отдельный явный отказ. Переписывание канона сбрасывает continuation, пробный повтор сохраняет.

Текущее обновление разговора и проверки: `outputs/FINAL_CONVERSATION_UPDATE.md`. Первоначальный отчёт: `outputs/CHAPTER_05_IMPLEMENTATION_REPORT.md`. Предыдущие отчёты описывают свои исторические выпуски. Сайт не опубликован.

## Telegram Mini App

При запуске запрашивается полноэкранный режим Telegram (Bot API 8.0+). Если клиент не поддерживает его или отклоняет запрос, игра остаётся развёрнутой на доступную высоту. Отступы учитывают вырез, системную панель и элементы Telegram; выход из полноэкранного режима остаётся под контролем пользователя. Реальный iPhone проверяет владелец.

Экспорт в Mini App: «Скачать копию прогресса» открывает выбор «Скачать через браузер» или «Скопировать текст копии». Внешний браузер получает именно выбранную Telegram-копию и показывает отдельную страницу с кнопкой «Скачать файл», не импортируя её в браузерную игру. В настройках доступно «Вставить текст копии» с обычной проверкой и подтверждением замены. Если ссылка слишком длинная или браузер не открылся, можно вручную скопировать текст. Обычное скачивание в браузере прежнее.

[Открыть игру в Telegram](https://t.me/our_little_story_game_bot/story) — отдельная ссылка Mini App, созданная владельцем. Её можно отправлять игроку напрямую; ссылка в настройках сайта ведёт сюда.

Бот: [@our_little_story_game_bot](https://t.me/our_little_story_game_bot). Владелец настраивает кнопку игры через `/setmenubutton` в BotFather, URL — https://vlad28x.github.io/our-little-story/ . Собственный сервер и запущенный процесс бота не нужны; ответов на /start нет. Main Mini App — дополнительная настройка профиля. Полная инструкция, протокол сохранения и границы проверки: [outputs/TELEGRAM_MINI_APP.md](outputs/TELEGRAM_MINI_APP.md).

Именно при запуске кнопкой Mini App подключается официальный Telegram WebApp script. CloudStorage хранит историю/альбом/настройки/права текущего пользователя и бота. При загрузке сначала проверяется облако; новый клиент восстанавливает историю, разные копии требуют явного выбора, а сетевые ошибки не перезаписывают облако. На устройстве остаётся отдельная резервная копия. Обычные браузерные сохранения и кеши других Telegram-аккаунтов не смешиваются. Обычный Chrome не синхронизируется с Telegram автоматически — перенос через JSON. Настоящий выбор встречи и черновик сообщения остаются локальными.

На одну облачную запись разрешено 4096 символов, поэтому envelope хранится в проверяемых частях двух банков с переключением head после успешной записи. Поддерживается одно активное устройство; у CloudStorage нет compare-and-swap. Нужно дождаться надписи «История сохранена в Telegram» перед закрытием. Заглушки SDK проверены автоматически, а настройка BotFather и настоящий вход на телефоне/втором устройстве требуют проверки владельца. Токены бота и личные данные не включены в проект.
