# Пять случайных встреч

Русскоязычная мобильная визуальная новелла на React, TypeScript и Vite. Локальная редакция на 27 ноября 2026 года использует `schemaVersion: 1`, `CONTENT_VERSION: 26` и `scriptRevision: 7` в главе 8.

При загрузке сохранения content25 обновление сохраняет главы 1–7, их открытки, достижения, ответ на приглашение после пятой, настройки и все открытые главы; главы 8–10 начинаются заново (а незавершённая активная 6–7 сбрасывается только в пределах текущей главы). При загрузке сохранения content24 с завершённой пятой главой обновление сохраняет главы 1–5. Для редакций до content24 начинается новое прохождение с прежними настройками и доступом.

## Где сверяться

- Реплики, условия, варианты сцен и последствия, которые сейчас видит игрок, проверять в [src/content/chapters](src/content/chapters). Названия, порядок и доступ к главам задаёт [manifest.ts](src/content/chapters/manifest.ts).
- Для работы над новой сценой прочитать [сценарное ядро](outputs/NARRATIVE_CORE.md), [справочник персонажей](outputs/CHARACTER_BIBLE.md) и затронутые сцены. Для глав 6–10 также читать [основу второго сезона](outputs/SEASON_02_BIBLE.md).
- Для чтения текущего сценария по главам использовать [оглавление](outputs/AGENTS.md). При правке сюжета обновлять соответствующее Markdown-зеркало и проверять выбранные пути.
- Датированные черновики и прежние редакции сохранены в локальном `work/outputs-archive-2026-11-23/`. Обращаться к ним для истории конкретного решения. Новое прямое поручение владельца определяет объём работы.

## Работа с проектом

- Сценарий хранится в типизированном графе. Условия и эффекты обрабатывает движок, UI отображает состояние. При изменении идентификаторов, порядка реплик, условий или эффектов проверять восстановление сохранённых сцен.
- Основное прохождение, пробные повторы, альбом и тестовые сохранения изолированы. Для проверок использовать синтетический прогресс и `?dev=1`. Рабочие копии игрока в браузере и Telegram сохранять.
- Для арт-правок использовать [визуальную основу](outputs/ART_DIRECTION.md) и художественные референсы. Оригинальные фотографии, переписки, данные профиля, коды и токены держать вне публичных материалов.
- Выбирать минимальные проверки под изменения. Для Markdown проверять изменённые ссылки и пути. Для сценария проверять затронутую главу и её ключевую развилку. Для интерфейса делать короткую проверку изменённого экрана на телефоне. Полный браузерный набор запускать по запросу, при подготовке выпуска или при изменении общей логики, влияющей на много путей. [Команды проверок](README.md#проверки-и-сборка)
- Коммит и публикация требуют отдельного поручения владельца. Подключать субагентов по прямому поручению.
