## 2. Этап A — основание и контент первой главы

Работа:

1. Проверить существующие файлы/инструкции и состояние git, не перетирать документы.
2. Создать Vite/React/TS strict, базовый CSS и npm scripts: dev, build, preview, typecheck, lint, test:unit, validate:content, test:smoke.
3. Реализовать закрытые типы и пять видов узлов. Без class-иерархий и без исполняемых выражений из строк.
4. Создать manifest пяти глав: только первая available. Перенести точные реплики, choices и IDs из CHAPTER_01_SCRIPT. Не сокращать реплики до «TODO: разговор».
5. Step с expectedTurn, маршрутизацией, проверкой результатов и атомарным завершением. Состояние `{}` на старте.
6. Добавить валидатор ссылок, доступных вариантов, ассетов (черновой manifest тоже должен быть явным), достижимых end и автоматических циклов.

Готово, когда: типизация проходит; три финала достижимы тестом; все условные переходы имеют fallback; повтор одной команды не меняет состояние второй раз; отсутствующий/чужой ID не ломает историю. Никакого внешнего доступа или готового арта для этого не требуется.

## 3. Этап B — первая играемая глава

Работа:

1. App + GameProvider + hash-навигация. Старт, карта, сцена, результат, минимальная пауза.
2. DialogueBox, ChoiceList, SceneStage; мгновенный текст по умолчанию, доступный фокус и кнопки 48 px.
3. TokenSearch: 6 областей, 3 жетона, секрет, помощник/пропуск, три результата. Всё управление тапами и клавиатурой.
4. Сохранение одной основной линии после каждого действия, backup и предупреждение об отказе storage. Перезагрузка диалога не повторяет выбор.
5. На end — соответствующая карточка, достижение и сохранённое завершение. Недоступные главы честно подписаны.

Готово, когда: все контрольные маршруты сценария пройдены вручную; storage roundtrip работает; перезагрузка на любом видимом узле безопасна; поиск после refresh корректно начинает только своё событие; кнопка назад/меню не стирает прогресс; нет невидимого выбора из-за высоты экрана.

Первая демонстрация может использовать простые нейтральные иллюстративные блоки, но имеет видимую маркировку «Черновой визуал». Это не финальная художественная приёмка и не версия для отправки девушке.

## 10. Риски и границы решений

- **Дрейф лица при генерации:** единый лист, фиксированный холст, проверка каждой позы; сокращать число поз, а не узнаваемость.
- **Повторы шуток:** одна завязка, вариация, возвращение в финале; не повторять один панч пять раз.
- **Разрастание веток:** общий сюжетный узел после 1–2 различающихся сцен; новые флаги только при конкретном потребителе.
- **Слишком короткая/длинная глава:** плейтест до производства всех иллюстраций; менять ритм и материал, не искусственную скорость интерфейса.
- **Хрупкое сохранение:** один envelope, валидатор, backup, экспорт, fixtures миграций.
- **Неодинаковый Telegram:** проверять возможности, показывать fallback; не обещать общую localStorage между браузерами.
- **Неполные исходные данные:** аккаунт GitHub/репозиторий, Telegram username, точный список лицензированного звука не предоставлены. Они не блокируют локальную реализацию; не выдумывать их. Для версии 1 адресат сообщения выбирается самим игроком.
