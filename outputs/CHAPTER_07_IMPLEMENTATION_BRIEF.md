## 3. Модель интерактива «Между строк»

### Данные без текста в сохранении

```ts
type TopicAnswer = 'question' | 'challenge' | 'ordinary';
type PlaceAnswer = 'lead' | 'invite' | 'stay';
type ToneAnswer = 'direct' | 'playful' | 'quiet';
type CouncilPrefix = [] | [TopicAnswer] | [TopicAnswer, PlaceAnswer];
type CouncilAnswers = CouncilPrefix | [TopicAnswer, PlaceAnswer, ToneAnswer];
type CouncilDraft = {
  kind: 'between-lines';
  answers: CouncilAnswers;
  phase: 'choose' | 'reply' | 'complete';
  lineIndex: number;
};
type CouncilResult =
  | {kind:'between-lines'; outcome:'completed'; answers:[TopicAnswer,PlaceAnswer,ToneAnswer]}
  | {kind:'between-lines'; outcome:'skipped'; answers:CouncilPrefix};
type CouncilAction =
  | {kind:'answer'; answer:TopicAnswer|PlaceAnswer|ToneAnswer}
  | {kind:'next-line'};
```

`Run.activity` становится `RouteDraft | CouncilDraft`; results получает optional 'between-lines'; GameResult включает CouncilResult. У каждой главы допустимы только её игры/activity, не разрешать обе формы в одной сцене. Результаты6 остаются прежними. В game-action добавить ветку game='between-lines'; runtime проверяет answer по текущему раунду, хотя TypeScript объединяет ID.

Строки сценария мини-игры держать в одном `src/content/betweenLines.ts`: три prompt-ситуации, по два совета, по три кнопки и девять последовательностей реакций. Это тот же Line[]/Speaker/Emotion, что в обычных диалогах. Модель может читать длины реакций из этого модуля без зависимости от React. Не копировать тексты в модель, тестовые fixtures и сохранения. nodeId во всей игре — c7.council; внутренний курсор хранит activity.lineIndex.

### Переходы и checkpoint

| Состояние | Разрешено | Следующее |
|---|---|---|
| Вход | Инициализация один раз через settle | answers=[], phase=choose, lineIndex=0 |
| choose с n=0..2 ответами | answer из набора раунда n | append; phase=reply, lineIndex=0; первая spark.voice при n=0 |
| reply с n=1..3 | next-line | Следующая строка реакции n−1 |
| Последняя строка reply, n<3 | next-line | phase=choose, lineIndex=0; ответы неизменны |
| Последняя строка reply, n=3 | next-line | phase=complete, lineIndex=0 |
| complete | game-result completed, answers точно совпадают | Сохранить результат, удалить activity, дать exchange, перейти к after.route |
| choose | game-result skipped, answers точно совпадают | Сохранить префикс, удалить activity, без exchange, перейти к after.route |

Нельзя отвечать второй раз в reply, менять прежний ответ, пропускать один раунд и продолжать более поздний, подтверждать completed до трёх реакций или подменять результат. UI формирует result из актуального draft; engine всё равно проверяет полное совпадение. Пропуск доступен только в choose: после уже начатой реакции пользователь дочитывает её, затем пропускает оставшиеся ситуации. В complete показывается только возврат к прогулке.

Советы ангела/дьяволёнка — **локальное состояние отображения**, без game-action и revision. После reload совет закрыт; уже принятые ответы, phase и lineIndex восстановлены. Это намеренное поведение, не потеря прогресса. Не записывать историю открытия советов или время нажатий.

Каждая принятая команда answer/next-line/result увеличивает run.turn обычным способом; stale expectedTurn отклоняется. Все команды проходят через reducer/persist, запрещены при suspended. Ошибка сохранения использует существующий recovery UI. Никаких игровых переходов и выдачи искр из useEffect/render. Разрешённый no-op не должен выдавать новую награду или создавать новую revision.

`betweenLinesReduce(draft, action)` чистая, не использует время/случайность. `validCouncilDraft`, `validCouncilResult`, `acceptsCouncilResult` проверяют точный набор ключей, tuple длину/позиции/значения, фазу и диапазон lineIndex. Для choose/complete lineIndex строго0; choose len≤2, reply len1..3, complete len3. Пауза и reload в середине третьей реакции не переводят её в complete.

### Игровые последствия

- Первая искра выдаётся при фиксации первого ответа, остаётся при дальнейшем пропуске. Вторая — только при принятии полного результата. Третья — обычный эффект выбора дистанции.
- Миссия вычисляется из guide и результата (topic question / place lead), не из просмотра совета. При пропуске после первого question миссия angel выполнена, но полный конверт не доступен.
- Место берётся из draft.answers[1] внутри игры и result.answers[1] после неё. lead/invite — план у арки; stay/отсутствует — план у окна. Пропуск не возвращает героев обратно. Это оформление сцены, не новая сохранённая копия результата.
- Третий ответ выбирает after.route. При неполном результате третьего ответа нет, идём в after.skipped.
- Все три финала доступны при всех40 вариантах результатов: 27 completed + 1 skipped без ответов + 3 skipped после первого + 9 skipped после второго.

Строки статуса миссии на результате: angel+question → «Задала свой вопрос»; devil+lead → «Выбрала поворот»; выбранный советчик без условия → «Разговор пошёл своим путём»; none → «Без миссии». Без слова «провал», красной отметки или скрытой оценки.

### CloudStorage и перенос

preserveLocalNotes копирует локальную **карту обеих глав**, включая валидную резервную копию при recovery. Новое устройство показывает «Личная заметка осталась на другом устройстве» только если status saved и совпадающего местного текста нет. deleted показывает прежний статус удаления; skipped не изображать как потерянный ответ. Ручной JSON-экспорт содержит обе заметки, предупреждение о личном тексте сохранить. Не менять chunk-протокол Telegram ради одной главы, не добавлять частые фоновые запросы.
