## Технические ограничения

1. React, TypeScript strict, Vite, обычный CSS; runtime-зависимости по умолчанию только react/react-dom. Без backend, Firebase, Supabase, БД, логина, аналитики и тяжёлого игрового движка. По новому поручению разрешён официальный Telegram WebApp script и CloudStorage только для Mini App; сторонний SDK-пакет не добавлен.
2. Сценарий — типизированные данные; step чистая; UI отображает состояние. Не размещать диалоги и условия всей истории внутри JSX.
3. Узлы dialogue/choice/route/minigame/end. Сохранять IDs, выбирать эффекты по закрытому словарю. Не eval и не JavaScript в импортируемом контенте.
4. Одно направление состояния: reducer → новая версия → persistence. Не менять сюжет из таймеров UI, аудио и анимаций.
5. Сохранение после каждого логического действия; двойной тап защищён expectedTurn. Один envelope, backup, валидация, экспорт/импорт; нельзя молча обнулить несовместимое сохранение.
6. Коллекция, trial и текущая история разделены. Пробный повтор не переписывает канон. Изменение истории удаляет последующие результаты только после понятного подтверждения.
7. GitHub Pages base из единого config; все public assets через BASE_URL. Hash-навигация, никаких серверных rewrite. Проверять сборку из подпапки и refresh.
8. Dev-панель изолирована от production и обычного сохранения. Не хранить настоящие секреты во frontend env.
9. Версии зависимостей фиксировать lockfile; новые пакеты добавлять только для конкретной недостающей возможности, объясняя причину.
10. Не создавать заранее пустую структуру всех будущих модулей. Глава 1 работает при `available:false` остальных глав.

- Голос Влада преимущественно lowercase с нормальной орфографией. Не спамить «ахах», вопросами, прозвищами и программистскими метафорами.

- Никаких очков любви/совместимости/правильности границ. Мини-игровой результат влияет на событие, а не достоинство игрока или доступ к отношениям.

Предварительная договорённость героев — часть вымышленной истории, не согласие игрока на реальную встречу. ## Арт, приватность и коммуникация

- Оригинальные шесть фотографий и профиль Telegram не включать в public, git, dist, экспорт сохранения или поставляемый архив. Работать с художественными производными и обезличенными правилами.

- Никакой автоматической отправки в Telegram и скрытого сбора. Share/copy/download запускаются только отдельным действием. Не считать закрытие share доказательством отправки.
- Контакт и репозиторий неизвестны: не придумывать username/адреса. Реальный выбор continuation по умолчанию остаётся только на устройстве.
- Не создавать репозиторий, не push и не публиковать сайт без соответствующей авторизации пользователя. Локальную работу, исправления и проверки делать в пределах порученного этапа без лишних вопросов.

## Мобильность и доступность
