## Память прощания и возврат в пятой

В `StoryState` добавлено ровно одно новое сохраняемое поле:

```ts
c4Goodbye?: 'accept' | 'her' | 'none';
```

Три существующих выбора `c4.goodbye` записывают соответственно `accept`, `her`, `none`. Остальные сюжетные поля и награды от этого не меняются.

После всех реплик `c5.return` переход ведёт в `c5.hug.route`:

| Сохранённое значение | Продолжение |
|---|---|
| `her` | `c5.hug.her`, три реплики, `vlad.elegant.laugh` |
| `accept` | `c5.hug.accept`, три реплики, `vlad.elegant.smile` |
| `none` или поле отсутствует | Сразу `c5.rain.route`, без воспоминания об объятии |

Оба новых диалоговых узла используют `bg.cafe.sunset` и затем переходят в прежний `c5.rain.route`. Память берётся из story текущего прогона, унаследованного из канонической четвёртой главы; коллекция и пробный повтор четвёртой её не подменяют. Для пробной пятой используется её канонический startState, как у существующих возвратов.

Существующий reducer уже сохраняет story в active/trial, записях и startStates, поэтому отдельная логика хранения или новый тип действия не понадобились.

## Совместимость и версии

Оставлены **schemaVersion1 / contentVersion12**. Версии контента отдельных глав и scriptRevision3 второго сезона не изменены.

Причины:

1. Поле аддитивное и необязательное. Отсутствие означает неизвестный способ прощания, а не автоматически выбранное объятие или отказ.
2. Все прежние node ID и choice ID существуют. Старые dialogue-узлы не укорочены, поэтому прежние сохранённые индексы реплик остаются в допустимых пределах. Сохранённый индекс не пересчитывается: при восстановлении внутри расширенного блока могут появиться добавленные реплики, но глава не перезапускается и решения не сбрасываются.
3. Новая развилка расположена после существующего `c5.return`. Старые копии, которые уже прошли это место, не перематываются обратно и не получают выдуманную память.
4. Миграция старых копий и принудительное добавление значений не нужны.

В валидаторе поле разрешено начиная с четвёртой главы и проверяется по закрытому enum при наличии. Общая проверка обязательных story-полей делает исключение только для `c4Goodbye`; проверки других полей сохраняются. Исключение действует и для завершённых записей, и для startStates, и для активных сцен прощания, включая `c4.goodbye.hug`.

Добавлена проверка согласованности новых активных сцен пятой: `c5.hug.her` и `c5.hug.accept` не принимаются при другом/отсутствующем сохранённом значении.

Замороженные парсеры `src/legacy/r1` и `src/legacy/r2` не изменялись. Проверены их существующие фикстуры, включая `firstFive.json`: записи1–5 остаются равны исходным, без добавления `c4Goodbye`. Прежний механизм явного обновления старого второго сезона остаётся прежним.

JSON и Telegram CloudStorage сохраняют новое поле через существующую сериализацию. Проверены все три значения и чтение через новый экземпляр облачного клиента. Поддержка означает чтение старых копий новой версией; работа старого опубликованного клиента с новым полем до обновления приложения не заявляется.

Тестовый помощник `legacyContent` дополнен `prePolishSnapshot`: при создании синтетической старой копии он убирает неизвестное старому клиенту поле, ограничивает курсоры трёх расширенных диалогов прежними границами и не помещает новые узлы в старый журнал. Это только тестовый код; production-парсер ничего такого не удаляет. Проверки старого формата сравнивают результат с этой старой копией, а не с новым значением, которого старый клиент никогда не сохранял.
