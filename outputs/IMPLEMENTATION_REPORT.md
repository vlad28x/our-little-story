## Как запустить

Из корня проекта с установленными Node.js 22.12+ и npm:

```sh
npm ci
npm run dev
```

Адрес обычно `http://127.0.0.1:5173/`. Для готовой сборки:

```sh
npm run build
npm run preview
```

Открыть адрес preview, обычно `http://127.0.0.1:4173/`. Не открывать dist/index.html через file://. В специальной локальной среде текущего Codex npm можно вызвать через `node work/tooling/package/bin/npm-cli.js`; на обычном Node/npm это не требуется. Рабочая папка `work/` — только вспомогательные инструменты и проверки, в поставку и git не входит.

### Исправление загрузки изображений

После сообщения пользователя о пропавшем арте восстановлен локальный сервер на 127.0.0.1:5173. Устранён общий флаг ошибки SceneStage, который скрывал фон, персонажа и кота при сбое всего одного изображения. Ошибки теперь относятся к конкретному URL; смена эмоции не наследует ошибку старого спрайта. Кнопка повторяет только неудачные запросы с обновлённым URL, не меняя игровой курсор. Сообщение стало компактным, остальные слои сцены остаются на экране.

Перед исправлением новый тест воспроизвёл исчезновение рабочего фона при ошибке спрайта. После исправления все три проверки ошибок и все семь прежних браузерных сценариев проходят. Дополнительно проверен живой dev-сервер: фон, Влад и Пончик загружены, ошибок запросов нет. TypeScript, ESLint и production-сборка повторно прошли. В README добавлено пояснение: сервер должен оставаться запущенным во время локальной игры.

Версии фактической среды: Node 24.19.0, React 19.3.1, TypeScript 5.9.3, Vite 7.3.7, Vitest 5.0.5, Playwright 1.64.1. Разрешённые версии закреплены lockfile.
