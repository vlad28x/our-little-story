## Подготовка runtime-ассета для Sol

На этапе реализации изготовить прозрачный WebP из утверждённого PNG, отдельное имя `angel-peek-r3.webp`, ориентир ширины600–700px, без изменения лица/позы/рук. Не перезаписывать старый `angel.webp`. Добавить источник в ASSET_CREDITS и новый ключ assetManifest, например adviser.angel.peek. Не использовать скриншот с UI как ассет.

На рисунке вертикальный срез торса расположен примерно на19% ширины исходника. Это предварительная визуальная оценка; измерить реальный край при постановке. Совместить его с левой границей сцены; пальцы выступают за линию среза и должны остаться видимыми. Не подменять alpha-срез нарисованной полоской, зеркальной копией руки или грубым прямоугольным clip-path.

У верхнего нимба небольшой запас, у нижнего края одежда почти доходит до границы изображения: не добавлять тень/transform, которая обрежет нимб/кисть, и не рассчитывать положение по пустой ширине холста. При необходимости padding для экспортного контейнера допустим, перерисовка утверждённой позы — только отдельная правка.

## Два разных масштаба дьявола

| Использование | Исправление |
|---|---|
|Секрет на открытке5|Меньше на телефоне: исходный квадрат110–126px вместо текущего минимума176px. Кисть держится за правый край, лицо основного Влада свободно. Диалог приглашения остаётся отдельным компонентом.|
|Короткий советчик6–10|Больше и выше: видимый портрет примерно140–158px по ширине на320–390px, центр портрета ориентировочно40–48% высоты сцены. Один активный советчик, основной Влад виден.|
|Ангел6–10|Сопоставимый **размер лица**, не одинаковый width PNG. Нимб/крыло не должны заставлять уменьшить лицо до старой маленькой фигурки. Слева, опора на край.|

Существующий devil-peek-cropped.webp уже подходит по позе; генерировать нового дьявола не требуется. Имеющиеся backgrounds8–10 и morning подходят, новый фон не нужен. Героиня остаётся POV без заданной внешности.
